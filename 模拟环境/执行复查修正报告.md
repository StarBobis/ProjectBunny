## F-110：区分空目标、模板和数值索引策略

- 原“五处相同空模板”描述不准确。正常 INI 会创建资源/变量模板；STATIC 的非有限选择可以没有实际元素，却被旧解析器当作成功目标，随后引用或间接绘制的 flags 消费者解引用空指针。动态 RING 的无效数值索引也可能让变量读取拿到空指针。
- STATIC 非有限值和无法解析到元素的目标在发布前拒绝；不可用模板的资源/变量 getter 不分配残缺对象；引用与间接绘制分别检查接收者。
- RING 数值索引无效时，变量读取返回明确的 NaN，不以零值伪装正常读取；写入保持现有不改槽/模板行为，已补入使用文档。
- FIFO/SPATIAL 用位模式键，已有真实回归支持 NaN UID。该功能、missing-read 默认模板、不分配策略、有限负数环绕和大数安全包裹都保留。不能把数值索引的 finite 检查搬到所有池类型之前。
- 原 GetElementIndex 的 SIZE_MAX 守卫已经正确，不重复修；验收见 `validation/F-110.json`。

## F-111：空辅助文件不是“打开失败后还继续”的同一场景

- 可复现路径是自动重编译但未请求导出，`fw` 合法为 null；全局日志存在且编译带诊断 blob 时，旧代码仍向该 null FILE 写注释。开启导出而打开失败的既有分支已经提前回退，不能混淆。
- 辅助文件写入有条件，编译成功后的输出处理继续；没有用 `if (!fw) return` 关闭合法自动修复。
- 旧 `GetFileTime(FILE*)` 使用了错误的参数类型，并可能发布未初始化时间。改为检查流与关闭结果，关闭后查询原生文件属性；查询失败输出零时间戳，不丢掉已成功生成的字节码。
- 初版装置未走生产初始化，中文路径在 C locale 下转换失败，未到目标写入；该轮结果不计缺陷证据。补真实配置初始化后复现 fast-fail，后续成功/失败/无日志/导出/时间戳故障专项与完整流程见 `validation/F-111.json`。

## F-138：安全 CRT 重载与多字节容量语义

- 原“转换错误后无 NUL 导致越界读”不适用于当前 MSVC 构建。两个安全 C++ 重载宏已开启，数组调用会转到 `wcstombs_s`，编码错误会清空目标；旧专项也确认 C locale 下转换失败不沿用静态缓冲区旧内容。
- 容量耗尽仍有真实问题：恰好写满字节容量时触发 CRT invalid-parameter 终止；多字节字符跨越剩余容量时，CRT 也可能成功返回一个截断前缀。配置限制的是宽字符数量，不能据此保证 UTF-8 字节容量。
- `_TRUNCATE` 加返回值检查的初版方案被专项拒绝：87 个中文字符仍返回了不完整前缀。最终方案先查询现有 locale 下完整字节数，连同 NUL 验证容量，再转换并核对结果；失败清空并诊断，不改变编码，不保留静默截断。
- 同段五个直接转换调用一并接入相同检查，转换失败不进入旧的纹理分量或列表解析。F-137 的合法转换后单字符越界另项处理，不合并提交。
- 专项覆盖 C/生产 UTF-8 locale、空白、精确边界、两类多字节超限、无效 UTF-16、恢复和真实 INI 重载；最终证据见 `validation/F-138.json`，共享消费者另做 DX12 兼容构建。
