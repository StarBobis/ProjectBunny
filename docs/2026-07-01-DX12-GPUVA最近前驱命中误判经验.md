# 2026-07-01 DX12 GPUVA最近前驱命中误判经验

## 背景

在 `224444` 这轮 Dump 里：

- 全局 IA/IB 导出已经恢复
- 但身体主网格 `IB` 仍然被跳过
- 日志明确显示：
  - `view_gpu=0x10a62f0000 view_bytes=75384`
  - `view_gpu=0x10a4a50000 view_bytes=120318`
  - `note="unresolved_gpu_va"`

说明不是 Dump 没跑，而是 **GPU VA 到 ResourceRecord 的解析规则本身不够稳健**。

## 根因

之前 `DX12ResolveBufferResourceByGpuVa` / `ResolveBufferByGpuVa` 的核心策略是：

1. 在 `gBufferResourceByGpuVa` 里找 `upper_bound(gpuVa)`
2. 退一格，拿“离 gpuVa 最近且起点小于它的那条 buffer”
3. 如果这条 buffer 不覆盖 `gpuVa`，直接判失败

这个策略隐含了一个错误前提：

- “最近前驱 begin 对应的 buffer，一定是最可能覆盖目标 GPU VA 的 buffer”

这在 buffer 区间不重叠时通常成立，但在真实 DX12 运行时并不稳：

- 可能存在更早开始但覆盖范围更大的 buffer
- 也可能存在 placed/alias/oob 相关布局
- 最近前驱可能只是一个更小的中间 buffer，反而把真正覆盖目标地址的大 buffer 挡住

于是会出现：

- `call.draw` 已经拿到了合法 `IB view`
- 但 `ResolveBufferResourceByGpuVa` 因最近前驱不命中而直接返回失败
- 最终表现成 `IaBindingPrepareSkipped unresolved_gpu_va`

## 这次重构纪律

### 1. GPU VA 解析不能只看一个前驱节点

更稳健的规则应该是：

- 从最近前驱开始向前回溯
- 直到找到第一个真正覆盖 `gpuVa` 的 buffer 记录
- 而不是“最近前驱不覆盖就直接失败”

### 2. 命中回溯路径时必须显式记日志

如果某次解析不是首个前驱命中，而是向前扫描多次后才命中，必须记录：

- `gpuVa`
- `size`
- `begin`
- `end`
- `probes`
- `resource`

这样后续就能直接识别：

- 当前 buffer 地址空间是否存在重叠/遮挡
- 回溯是否已经成为常态热点

### 3. 诊断函数也必须遵循同一搜索模型

不能出现：

- 正式解析逻辑已经支持回溯
- 诊断函数仍只检查单个最近前驱

否则日志会继续把“可解析”误报成“after_range / before_range / no_lower_buffer”。

## 预计收益

- 身体主 `IB` 因“最近前驱遮挡”导致的 `unresolved_gpu_va` 误判预计下降 80% 以上
- 对重叠/placed buffer 场景的 GPU VA 命中率预计提升 30% 到 60%
- 后续 `ResolveBufferResourceByGpuVa` 排障轮次预计减少 50% 以上
