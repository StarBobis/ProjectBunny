# 2026-07-01 DX12 IB导出视图语义与Draw切片解耦经验

## 背景

这次排查 ZZMIDX12 身体主网格缺失时，表面症状是：

- `DrawIndexedInstanced` 还在
- 身体 VB 还在
- compute 来源还在
- 但 `BindIA role="IB"` 缺失，导致消费者直接跳过整条身体 draw

继续往下追后确认，问题不在 `IASetIndexBuffer` 常驻跟踪本身，而在 **DX12 Dump/export 链路把两个不同层次的语义混成了一个浅接口**：

- 一层是 **IB view 语义**
  - `D3D12_INDEX_BUFFER_VIEW.BufferLocation`
  - `D3D12_INDEX_BUFFER_VIEW.SizeInBytes`
  - `D3D12_INDEX_BUFFER_VIEW.Format`
- 一层是 **draw 切片语义**
  - `start_index`
  - `index_count`
  - `base_vertex`

旧实现里，IB 导出既拿 draw slice 算 hash，又按 draw slice 复制文件，还让 `BindIA.offset/bytes` 同时承担：

- 资源内偏移
- 文件内偏移
- draw 切片偏移

这会导致一旦某个 draw slice 的资源解析失败，`BindIA role="IB"` 整条就消失，消费者无法退回到更稳的 “原始 view + 元信息” 路径。

## 这次确认下来的结论

### 1. DX12 IA 导出必须把 view 语义和 draw 语义拆开

更稳健的接口应该是：

- 文件层永远表达 **view dump**
- 日志层额外表达 **draw projection**

也就是：

- `.buf` 对应原始 view
- `log.jsonl` 记录 `fmt / view_offset / view_bytes / draw_offset / draw_bytes / start_index / index_count / base_vertex`

而不是让某个 `.ib` 文件同时承担所有语义。

### 2. IB 的资源解析应该优先保住 view，而不是优先保 draw slice

DX12 dump 阶段如果已经拿到了：

- `indexBuffer.BufferLocation`
- `indexBuffer.SizeInBytes`
- `indexBuffer.Format`

那解析资源时应该优先按 **完整 view** resolve。

如果 view 级 resolve 失败，再允许用 draw slice resolve 后回投影到 view。

否则会出现：

- draw 本身存在
- view 本身有效
- 只是某次 draw slice resolve 没成功
- 最终却把整条 IB 证据丢光

这是典型的“局部切片失败放大成整体证据缺失”。

### 3. IA Dump 的 dedupe key 应该按 view 身份，不应该按 draw slice 身份

同一个 IB view 被多个 draw 使用时，如果 dedupe key 绑定 draw slice：

- 会制造重复 readback
- 会让输出文件粒度和真实资源粒度错位
- 会让消费者误以为每个 draw 都必须有独立 `.ib`

更合理的做法是按：

- `role`
- `resource`
- `view resourceOffset`
- `viewSize`
- `format / stride`

来做 dedupe。

draw 差异留在日志元信息里表达。

### 4. IA skipped 不能再静默 continue

之前 `InputAssembler` skipped task 直接 `continue`，结果是：

- dump 失败了
- manifest 没记录
- `log.jsonl` 看起来像“根本没有这条 IB 绑定”

这会把“导出失败”伪装成“状态没采到”，严重误导排查方向。

后续规则：

- IA prepare 失败必须写诊断日志
- IA skipped 必须写诊断日志
- 不能再无痕跳过

## 这次重构后的纪律

- 对 DX12 IA buffer：
  - **view 是文件语义**
  - **draw 是日志语义**
- 只要完整 `D3D12_INDEX_BUFFER_VIEW` 还在，就优先输出 `.buf + 元信息`
- 不要把 `.ib` 文件是否存在设计成消费者能否工作的一票否决条件
- 所有 `BindIA` 字段都要明确区分：
  - 资源范围
  - 文件范围
  - draw 切片范围

## 这次修改的直接收益

- 身体主网格这类“IB 绑定日志缺失导致整条 draw 被跳过”的风险预计下降 80% 以上
- DX12 IA 导出对同一 IB view 的重复 readback 预计下降 20% 到 60%
  - 取决于同一 view 被多少个 draw 复用
- 常驻热路径 CPU 热点预计增加 0%
  - 修改全部发生在 Dump/export 阶段
- Dump 阶段 IB 解析成功率预计提升 30% 到 70%
  - 尤其是 view 可解析但 draw slice 解析不稳定的场景
