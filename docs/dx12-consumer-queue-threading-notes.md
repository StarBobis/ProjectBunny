# DX12 Consumer Queue Threading Notes

## 2026-07-01

- IA binding residency rule: `IASetVertexBuffers` / `IASetIndexBuffer` caller-thread hooks should not eagerly resolve GPUVA to tracked resources or take extra COM retains when the runtime only needs current Mod/pre-skin state and is not recording frame binding events. In that mode, keep only the lightweight `D3D12_*_BUFFER_VIEW` snapshot in `CommandListBindingState` and defer `DX12ResolveBufferResourceByGpuVa()` to actual IA queries/export paths. Eager resolve/retain is still required while F8/ShaderDump/frame binding events are being recorded, because queued `BindingEvent` objects must keep the referenced resources alive across later command-list mutations and frame boundaries.
- Binding event snapshot rule: once `SetPipelineState` has already refreshed and cached `pipelineShaderInfo` inside `CommandListBindingState`, do not call `RefreshPipelineShaderInfo()` again in `RecordStateEvent`, `RecordDraw*`, `RecordDispatch`, `RecordOutputTargets`, or clear-event wrappers before enqueue. Repeating the PSO-to-shader-info lookup on every event enqueue only burns caller-thread CPU and does not improve event correctness, because `BuildEvent()` already consumes the cached info and still has a fallback lookup if the cache is absent.

## 2026-06-30

- Do not move DXGI `Present`, command queue execution, or command-list mutation into the consumer queue. These APIs carry caller-thread ordering, window-message, or command-list instance ownership assumptions.
- Safe queue candidates are CPU metadata tasks that either copy plain descriptor structs immediately or retain COM objects before enqueue, then update our own tracker state under `gResourceLock` or `gDescriptorLock`.
- When queueing metadata that later feeds draw/dispatch lookup, add a drain at the read boundary. Otherwise the hot path can record a PSO index and immediately fail to resolve its root signature because the consumer has not processed the task yet.
- Keep public APIs stable and route them through queue-backed implementations with an immediate fallback. This makes call sites less fragile and keeps future queue expansion centralized.
- Logs can show the queue work is already off-thread while the hook wrapper remains hot. In that case, check for synchronous `JsonFuncFlush` and repeated policy predicates on the caller thread before moving more D3D-facing work.
- Descriptor view creation should keep the real D3D12 `Create*View` call on the caller thread. Only queue descriptor metadata after designing batching/backpressure; raw per-descriptor tasks are too bursty for the shared consumer queue.
- Failed attempt: moving all `Create*View` descriptor records into the shared resource collect queue caused descriptor bursts to grow pending work past 65k while the worker stayed behind. Do not put per-descriptor creation traffic on the same single consumer queue without coalescing, backpressure, or a dedicated descriptor pipeline.
- If descriptor metadata is revisited, prefer batching/range coalescing or a bounded latest-value cache keyed by CPU handle instead of one queue task per descriptor.
- Follow-up architecture: descriptor metadata now enters through `DX12DescriptorCollectPipeline` instead of `DX12ResourceCollectQueue`. The first adapter is intentionally synchronous, with drain hooks at descriptor read boundaries, so future batching or latest-value coalescing can be added without putting descriptor bursts back into the shared resource FIFO.
- Descriptor metadata now has a dedicated worker pipeline. Keep the real D3D12 `CopyDescriptors*` call on the caller thread; enqueue only our metadata update. Drain must wait for both pending and active descriptor tasks so descriptor queries cannot observe a half-applied async range.
- Failed design avoided: caller-side drain must not pop descriptor tasks while the worker is also consuming them, because that can process later descriptor ranges before earlier ranges and corrupt RenderDoc-like descriptor history. Use a single FIFO consumer and make drain wait for idle.
- Async descriptor tasks that carry resource pointers must retain resources before enqueue and release only the queue's temporary retain. Do not transfer queue ownership into the global descriptor tracker; tracker records are non-owning unless a future design explicitly changes that contract.
- Caller-thread capture rule: keep the actual D3D12 API invocation on the caller thread, and capture every fact that cannot be reconstructed later before returning. For descriptor tracking this includes descriptor kind, copied descriptor structs, source/destination CPU handles, range counts, and any referenced resource or counter-resource pointers that later dump reconstruction may need.
- Caller-thread ordering rule: any descriptor metadata path whose meaning depends on the current CPU descriptor memory image must preserve caller-thread order at the metadata boundary. `CopyDescriptors*` is a CPU-immediate descriptor memory copy, so tracker work may move off-thread only after prior pending descriptor writes are flushed or captured in-order, and only if the copy source data itself has already been captured.
- Caller-thread lifetime rule: when descriptor metadata is deferred, the caller thread must take temporary COM retains for queued resource pointers before enqueue. The consumer thread releases only those temporary queue retains after the tracker update commits.
- Two-stage async rule: split tracker work into stage 1 capture on the caller thread and stage 2 map/history updates on the consumer thread. Never move stage 1 behind a queue when DX12 offers no later introspection path to recover the original information.
- Failed attempt: merely giving descriptor metadata its own worker queue is not enough. A run on 2026-06-30 produced `DX12DescriptorCollectPipeline` backlog `pending=225748`, `maxDepth=225748`, with hundreds of thousands of `Create*View` and `CopyDescriptors` metadata tasks. This caused a long apparent hang even though the worker eventually drained. Do not reintroduce one-task-per-descriptor async collection; a dedicated queue without batching/coalescing is still a burst amplifier.
- Required next descriptor design: coalesce before enqueue. `Create*View` metadata should be a bounded latest-value map keyed by destination CPU handle, and `CopyDescriptors*` metadata should stay as ranges or merged adjacent ranges. Add backpressure or synchronous fallback when pending grows beyond a small bounded budget, and log queue depth so descriptor bursts are visible immediately.
- Recovery decision: disable the descriptor worker queue and restore inline descriptor metadata collection until coalescing is implemented. Restoring inline behavior may bring back the original CPU hotspot, but it avoids the severe queue backlog/hang failure mode and is the safer baseline for testing.
- RenderDoc-aligned descriptor lesson: `CopyDescriptors*` is a CPU-immediate descriptor memory copy, not a queue command. Do not try to solve its CPU cost by enqueueing one task per copied descriptor. Keep the real API call on the caller thread and make our metadata mirror cheap: descriptor heap slots should behave like a lightweight slot array, while the CPU descriptor ledger keeps the heavier descriptor details for fallback queries.
- Slot-array ownership rule: heap slots and slot history should not multiply COM ownership during descriptor copy storms. Copy descriptor values into slots as non-owning mirrors; use the resource tracker/CPU ledger to supply detailed resource metadata. Reintroducing per-copy `CloneDescriptorRecord`/`AddRef` in slot-to-slot copies brings back the original CPU hotspot.
- Descriptor pipeline reduction rule: keep the existing `DX12DescriptorCollectPipeline` layer, but do not log every descriptor write/copy. A 2026-06-30 run produced more than 3.3M pipeline log entries, dominated by `RecordCopyRangeInline` and `RecordDescriptorInline`. Use aggregate stats and merge strictly contiguous copy ranges before applying tracker updates. Flush pending copy ranges before descriptor writes, snapshot queries, and shutdown to preserve order.
- RenderDoc-aligned residency rule: full descriptor slot history is a capture-window feature, not a permanent Mod/Hunting background ledger. Keep current descriptor slots and the CPU descriptor ledger resident so Mod and F8 can resolve current bindings, but gate `slotHistory`/epoch appends behind FrameAnalysis capture/request state. Leaving `NeedsFullDescriptorHistory()` always true caused every descriptor copy storm to allocate history entries even when no F8 frame was being captured.
- Descriptor slot copy optimization rule: when both source and destination CPU handles resolve to tracked descriptor heap slots, copy the contiguous heap span as a range. Do not call the per-slot helper for every descriptor unless the source is missing and must fall back to the CPU descriptor ledger. For same-heap overlapping ranges, snapshot the source span first so the tracker mirrors CPU descriptor copy semantics instead of reading values it just wrote.
- CPU descriptor ledger ownership rule: do not store a duplicate ledger clone for descriptors that are already mirrored in tracked heap slots. The ledger is a fallback for heap-external CPU descriptors and non shader-visible/staging heap descriptors that can later become `CopyDescriptors*` sources. Duplicating shader-visible/current slot entries in both `slots` and `gDescriptorByCpuHandle` adds Clone/AddRef and snapshot work without improving Mod/F8 binding resolution.
- Resource queue logging rule: resource creation metadata is still required for F8 texture/buffer dumps because resources may be created long before the capture window. Do not solve that by dropping texture/resource tracking. Instead, avoid per-resource queue stage logs (`Enqueue`, `Dequeue`, `ProcessResourceBegin`, `ProcessResourceComplete`) and use aggregate queue stats plus slow-task samples, so queue diagnostics remain available without synchronous formatting on every resource task.
- Resource create hook logging rule: keep the actual D3D12 resource creation call and metadata enqueue unchanged, but do not log every `OriginalBegin`, `OriginalEnd`, `HookReturn`, `RecordRawResource`, `EnqueueBegin`, `EnqueueEnd`, and `Return` stage for every resource. Use periodic aggregate counters and always log failures/fallbacks. Reintroducing per-resource stage logs makes the hook wrapper look hot even when the real resource metadata work is already queued.
- Descriptor query batching rule: after slot-array and ledger reductions, the next CPU hotspot can move to query-side descriptor resolution. Do not call `DX12FindDescriptorSummaryByCpuHandle` once per table slot in current-binding/output-binding paths; that repeats descriptor pipeline drains and lock transitions. Use a batch query that drains once, fills lightweight summaries under one descriptor shared lock, then completes resource info under one resource shared lock.
- Light descriptor query rule: a function named `DX12FindDescriptorSummaryByCpuHandleLight` must stay truly light. CBV GPUVA-to-resource completion can grab the resource lock and should be performed only by full or batch-completion paths. Reintroducing implicit CBV completion inside light queries makes range queries look cheap in code while still behaving like per-descriptor full queries.
- Tracking policy rule: do not leave `NeedsDescriptorTracking()` / resource creation tracking hardcoded to `true` as a safety blanket. That makes ordinary injection pay the Hunting/F8 descriptor-copy and resource-index cost even when no Mod feature, Hunting mode, ShaderDump, or frame dump needs it. Gate heavy tracking by actual runtime demand, while preserving full tracking once Hunting/F8/ShaderDump or descriptor-driven Mod features are active.
- F8 residency correction: do not gate descriptor creation metadata or resource creation metadata entirely behind active F8/Hunting state. F8 needs resources and source descriptors that were created long before capture was requested, and DX12 descriptor handles cannot be introspected later to recover the resource. If reducing ordinary injection overhead, first gate the high-churn `CopyDescriptors*` slot mirror/history work, while keeping resource records and created descriptor records resident enough for later dump reconstruction.
- F8 summary freeze lesson: do not run summary-style binding reconstruction in the dump completion path. A 2026-06-30 run froze after priming about 102k descriptor slots and then repeatedly calling epoch descriptor-history queries while producing `summary` files. `CopyDescriptors*` is CPU-immediate descriptor memory copying, and descriptor handles cannot be introspected later, so recovering every historical draw/dispatch binding by scanning descriptor history is a separate expensive analysis product, not required for writing actual dumped resources. F8 should skip `summary` files and avoid descriptor-history priming unless a future feature explicitly asks for those reports.
- F8 summary removal rule: do not keep dormant `summary` directory writers as fallback or "maybe useful later" code. If F8 needs extra diagnostics, write aggregate records to `log.jsonl` or the existing manifest stream. Leaving `summary\\*.csv` / `summary\\*.txt` writers in the tree makes future fixes accidentally re-enable expensive binding reconstruction and violates the dump contract that resource files plus logs are the supported output.
- F8 discovery mode lesson: F8 resource dumping must not depend on the UI Hunting runtime mode. Capture completion calls `EndCapture()` before `DX12DumpFrameAnalysis()`, and users can request F8 while the runtime mode is still Mod. If metadata/resource discovery is guarded by `DX12RuntimeState::IsHuntingMode()`, dump creates only logs or summary leftovers and writes no resource files. Treat F8 dump as its own discovery request and keep summary-only PSO/resource reports out of that path.
- F8 discovery crash lesson: do not materialize every descriptor/resource discovery candidate into readback resources before writing files. A 2026-06-30 run scanned about 1.0M descriptors, queued 13k dump tasks and 324MB of buffer readbacks, then crashed before file output. Discovery must dedupe without storing duplicate alias tasks, keep per-class task/byte budgets, retain source resources for queued copy tasks, and skip the second tracked-resource inventory pass unless it is explicitly re-enabled after metadata discovery is stable.
- F8 empty-output exception lesson: a dump can show "complete" while producing only `log.jsonl` if `TryDumpCurrentFrameResources` catches an SEH exception before `ResourceDumpTasksQueued`. The 2026-06-30 15:06 run created the frame directory and `deduped`, scanned metadata descriptors until about 1.07M / 1.08M, then hit `0xc0000005` and wrote no resource files. Keep per-descriptor prepare/file-name work behind small exception boundaries, stop metadata scanning once the frame task budget is full, and write exception details into the frame `log.jsonl`, not only the root log.
- F8 compute binding traceability lesson: buffer contents alone are not enough. If `DX12ResourceDump` leaves `bindings` empty, metadata discovery may still dump `.buf` files, but `log.jsonl` cannot answer which compute dispatch/root/register produced each file. Restore `DX12BindingResourceExport::GetCurrentFrameResourceBindings()` in the resource dump path, reuse that same binding vector for IA producer classification to avoid duplicate binding reconstruction, and write file/status/note on `BindResource` rows. Do not bring back `summary` folder writers or descriptor-history summary reconstruction for this.
- DirectX12 module locality rule: loose files under `src/DirectX12` hide ownership and make future F8 fixes easy to wire through the wrong seam. Keep `CMakeLists.txt` at the DirectX12 root and place implementation files in one-level module folders only, such as `binding`, `command`, `descriptor`, `frame_analysis`, `resource`, and `runtime`. Do not create nested module folders under those directories.
- F8 draw event traceability lesson: per-draw `call.draw` rows can be restored by running the existing binding trace export during F8 and writing event-serial `call_index` records. Keep this dump-only; do not add hot-path JSON formatting in `DrawIndexedInstanced`. If physical log order is not required, consumers can join `DrawIndexedInstanced`, `BindIA`, and `BindResource` by `call_index` / `eventSerial`. Real `ExecuteIndirect` argument expansion is a separate feature because DX12 requires interpreting the argument buffer through the command signature layout.
- GPUPreSkinning producer-chain lesson: `hunting_uav_state` only proves a buffer is currently UAV-written; it is not a real shader binding identity. When a pre-skin output is kept for later IA use, persist the producer compute UAV root/register metadata with the active output state, then have F8 export a `compute_cbv_srv_uav` `BindResource` row for the output buffer. Otherwise IA classification falls back to `producer_bind:"hunting_uav_state"` and `producer_reg:UINT_MAX`, which cannot be joined back to the producing dispatch.
- F8 IA producer priority rule: `hunting_uav_state` must be a fallback producer only. Do not let a later `hunting_uav_state` event override an earlier real `compute_cbv_srv_uav` producer that matches the same IA buffer range, because the fallback is resource-state evidence rather than binding identity. Log IA classification counts so a capture can show real producer rows, fallback rows, and ignored fallback candidates directly.
- Descriptor copy fast-path rule: optimize `CopyDescriptors*` inside the existing synchronous descriptor tracker by copying contiguous tracked heap slot spans, not by adding a worker queue or dropping the CPU descriptor ledger. Only use the fast path when the full source span is present in tracked heap slots and full descriptor history is not active; during F8/history capture or unresolved sources, fall back to the older per-slot path so Dump completeness wins over speed.
- Binding tracker async rule: queue only our binding metadata events, never command-list mutation itself. When deferring draw/dispatch/state event building, capture `descriptorEpoch` on the caller thread and feed that exact epoch into the worker-built `BindingEvent`; re-reading `CurrentDescriptorEpoch()` later can join the event to the wrong descriptor history generation.
- Binding tracker IA lifetime rule: `CommandListBindingState` already owns one retain for resolved IA buffers, but an async queue snapshot needs its own temporary retain before enqueue and must release that temporary retain after worker commit. Copying the state struct without extra retains lets later `IASetVertexBuffers` / `IASetIndexBuffer` mutations free the resource before the worker consumes the task.
- Binding tracker drain rule: once draw/dispatch/output events move to a worker queue, every read boundary that exports or snapshots frame bindings must drain first, and `BeginFrame()` must drain before clearing tracked vectors. Otherwise export can observe half-applied events or the worker can append into containers that the present thread just reset.
- Binding tracker PSO cache rule: if worker-built events need PSO shader info, cache `pipelineState -> DX12PsoShaderInfo` in `CommandListBindingState` when `SetPipelineState` runs. This removes repeated `DX12GetPipelineStateShaderInfo()` lookups from per-draw event construction and avoids worker dependence on reconstructing metadata that was already known on the caller thread.
