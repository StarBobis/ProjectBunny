# DX12 Consumer Queue Threading Notes

## 2026-06-30

- Do not move DXGI `Present`, command queue execution, or command-list mutation into the consumer queue. These APIs carry caller-thread ordering, window-message, or command-list instance ownership assumptions.
- Safe queue candidates are CPU metadata tasks that either copy plain descriptor structs immediately or retain COM objects before enqueue, then update our own tracker state under `gResourceLock` or `gDescriptorLock`.
- When queueing metadata that later feeds draw/dispatch lookup, add a drain at the read boundary. Otherwise the hot path can record a PSO index and immediately fail to resolve its root signature because the consumer has not processed the task yet.
- Keep public APIs stable and route them through queue-backed implementations with an immediate fallback. This makes call sites less fragile and keeps future queue expansion centralized.
- Logs can show the queue work is already off-thread while the hook wrapper remains hot. In that case, check for synchronous `JsonFuncFlush` and repeated policy predicates on the caller thread before moving more D3D-facing work.
- Descriptor view creation should keep the real D3D12 `Create*View` call on the caller thread. Only queue descriptor metadata after designing batching/backpressure; raw per-descriptor tasks are too bursty for the shared consumer queue.
- Failed attempt: moving all `Create*View` descriptor records into the shared resource collect queue caused descriptor bursts to grow pending work past 65k while the worker stayed behind. Do not put per-descriptor creation traffic on the same single consumer queue without coalescing, backpressure, or a dedicated descriptor pipeline.
- If descriptor metadata is revisited, prefer batching/range coalescing or a bounded latest-value cache keyed by CPU handle instead of one queue task per descriptor.
- Follow-up architecture: descriptor metadata now enters through `DX12DescriptorCollectPipeline` instead of `DX12ResourceCollectQueue`. The first adapter is intentionally synchronous, with drain hooks at descriptor read boundaries, so future batching or latest-value coalescing can be added without putting descriptor bursts back into the shared resource FIFO.
- Descriptor metadata now has a dedicated worker pipeline. Keep the real D3D12 `CopyDescriptors*` call on the caller thread; enqueue only our metadata update. Drain must wait for both pending and active descriptor tasks so descriptor queries cannot observe a half-applied async range.
- Failed design avoided: caller-side drain must not pop descriptor tasks while the worker is also consuming them, because that can process later descriptor ranges before earlier ranges and corrupt RenderDoc-like descriptor history. Use a single FIFO consumer and make drain wait for idle.
- Async descriptor tasks that carry resource pointers must retain resources before enqueue and release only the queue's temporary retain. Do not transfer queue ownership into the global descriptor tracker; tracker records are non-owning unless a future design explicitly changes that contract.
- Failed attempt: merely giving descriptor metadata its own worker queue is not enough. A run on 2026-06-30 produced `DX12DescriptorCollectPipeline` backlog `pending=225748`, `maxDepth=225748`, with hundreds of thousands of `Create*View` and `CopyDescriptors` metadata tasks. This caused a long apparent hang even though the worker eventually drained. Do not reintroduce one-task-per-descriptor async collection; a dedicated queue without batching/coalescing is still a burst amplifier.
- Required next descriptor design: coalesce before enqueue. `Create*View` metadata should be a bounded latest-value map keyed by destination CPU handle, and `CopyDescriptors*` metadata should stay as ranges or merged adjacent ranges. Add backpressure or synchronous fallback when pending grows beyond a small bounded budget, and log queue depth so descriptor bursts are visible immediately.
- Recovery decision: disable the descriptor worker queue and restore inline descriptor metadata collection until coalescing is implemented. Restoring inline behavior may bring back the original CPU hotspot, but it avoids the severe queue backlog/hang failure mode and is the safer baseline for testing.
- RenderDoc-aligned descriptor lesson: `CopyDescriptors*` is a CPU-immediate descriptor memory copy, not a queue command. Do not try to solve its CPU cost by enqueueing one task per copied descriptor. Keep the real API call on the caller thread and make our metadata mirror cheap: descriptor heap slots should behave like a lightweight slot array, while the CPU descriptor ledger keeps the heavier descriptor details for fallback queries.
- Slot-array ownership rule: heap slots and slot history should not multiply COM ownership during descriptor copy storms. Copy descriptor values into slots as non-owning mirrors; use the resource tracker/CPU ledger to supply detailed resource metadata. Reintroducing per-copy `CloneDescriptorRecord`/`AddRef` in slot-to-slot copies brings back the original CPU hotspot.
- Descriptor pipeline reduction rule: keep the existing `DX12DescriptorCollectPipeline` layer, but do not log every descriptor write/copy. A 2026-06-30 run produced more than 3.3M pipeline log entries, dominated by `RecordCopyRangeInline` and `RecordDescriptorInline`. Use aggregate stats and merge strictly contiguous copy ranges before applying tracker updates. Flush pending copy ranges before descriptor writes, snapshot queries, and shutdown to preserve order.
- RenderDoc-aligned residency rule: full descriptor slot history is a capture-window feature, not a permanent Mod/Hunting background ledger. Keep current descriptor slots and the CPU descriptor ledger resident so Mod and F8 can resolve current bindings, but gate `slotHistory`/epoch appends behind FrameAnalysis capture/request state. Leaving `NeedsFullDescriptorHistory()` always true caused every descriptor copy storm to allocate history entries even when no F8 frame was being captured.
- Descriptor slot copy optimization rule: when both source and destination CPU handles resolve to tracked descriptor heap slots, copy the contiguous heap span as a range. Do not call the per-slot helper for every descriptor unless the source is missing and must fall back to the CPU descriptor ledger. For same-heap overlapping ranges, snapshot the source span first so the tracker mirrors CPU descriptor copy semantics instead of reading values it just wrote.
- CPU descriptor ledger ownership rule: do not store a duplicate ledger clone for descriptors that are already mirrored in tracked heap slots. The ledger is a fallback for heap-external CPU descriptors and non shader-visible/staging heap descriptors that can later become `CopyDescriptors*` sources. Duplicating shader-visible/current slot entries in both `slots` and `gDescriptorByCpuHandle` adds Clone/AddRef and snapshot work without improving Mod/F8 binding resolution.
- Resource queue logging rule: resource creation metadata is still required for F8 texture/buffer dumps because resources may be created long before the capture window. Do not solve that by dropping texture/resource tracking. Instead, avoid per-resource queue stage logs (`Enqueue`, `Dequeue`, `ProcessResourceBegin`, `ProcessResourceComplete`) and use aggregate queue stats plus slow-task samples, so queue diagnostics remain available without synchronous formatting on every resource task.
- Resource create hook logging rule: keep the actual D3D12 resource creation call and metadata enqueue unchanged, but do not log every `OriginalBegin`, `OriginalEnd`, `HookReturn`, `RecordRawResource`, `EnqueueBegin`, `EnqueueEnd`, and `Return` stage for every resource. Use periodic aggregate counters and always log failures/fallbacks. Reintroducing per-resource stage logs makes the hook wrapper look hot even when the real resource metadata work is already queued.
- Descriptor query batching rule: after slot-array and ledger reductions, the next CPU hotspot can move to query-side descriptor resolution. Do not call `DX12FindDescriptorSummaryByCpuHandle` once per table slot in current-binding/output-binding paths; that repeats descriptor pipeline drains and lock transitions. Use a batch query that drains once, fills lightweight summaries under one descriptor shared lock, then completes resource info under one resource shared lock.
- Light descriptor query rule: a function named `DX12FindDescriptorSummaryByCpuHandleLight` must stay truly light. CBV GPUVA-to-resource completion can grab the resource lock and should be performed only by full or batch-completion paths. Reintroducing implicit CBV completion inside light queries makes range queries look cheap in code while still behaving like per-descriptor full queries.
- Tracking policy rule: do not leave `NeedsDescriptorTracking()` / resource creation tracking hardcoded to `true` as a safety blanket. That makes ordinary injection pay the Hunting/F8 descriptor-copy and resource-index cost even when no Mod feature, Hunting mode, ShaderDump, or frame dump needs it. Gate heavy tracking by actual runtime demand, while preserving full tracking once Hunting/F8/ShaderDump or descriptor-driven Mod features are active.
