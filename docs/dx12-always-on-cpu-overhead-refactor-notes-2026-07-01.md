# DX12 Always-On CPU Overhead Refactor Notes

## 2026-07-01

- Hot-path skip correction: `skipAll` only skipping hook-side feature work is not enough. If tracking policy still keeps descriptor creation metadata, PSO/root-signature reconstruction, and query-side full completion permanently hot, CPU can keep burning cycles and starve GPU submissions even while the runtime appears to be "skipping" work.
- Descriptor create caller-thread dedupe correction: `Create*View` caller-thread `DescriptorValueUnchanged()` checks looked attractive, but production logs showed descriptor write replacement stayed extremely low while the check itself ran on every descriptor create. For bursty CBV/SRV/UAV creation, keep stable `valueId` capture but let the descriptor pipeline own coalescing and latest-value replacement.
- Query drain correction: root-signature and PSO-root lookups are resource-tracker metadata reads, not descriptor-content reads. Draining the descriptor pipeline in `DX12GetRootSignatureSummary()` / `DX12GetPsoRootSignature()` added cross-thread synchronization to unrelated queries and amplified dispatch-time CPU cost.
- Query lookup correction: once tracker-side maps like `gRootSignatureByPtr` and `gPsoRootByIndex` already exist, do not keep linear scans in snapshot/query helpers. Reintroducing vector scans silently turns metadata reads into hot-path O(n) work.
- Light-query naming rule: a function with `Light` in the name must stay light all the way through. If a light descriptor query re-enters resource completion or CBV GPUVA resolution, the call site will treat it as cheap while it still behaves like a heavy metadata query.
- Binding query laziness rule: do not resolve PSO shader info or infer root signatures for every descriptor query by default. First consume explicit command-list root signatures already tracked by `SetGraphicsRootSignature` / `SetComputeRootSignature`, then fall back to PSO-root reconstruction only when a query truly needs root table/register interpretation.
- Descriptor completion split rule: compute pre-skinning queries do not need identical completion depth for every descriptor type. SRV/UAV paths often work from creation-time view facts and resource pointers already captured in descriptor records, while CBV paths still need GPUVA-backed resource completion more often. Keep CBV on the full path when required, but let UAV/SRV stay on the lighter path unless a concrete consumer proves otherwise.
