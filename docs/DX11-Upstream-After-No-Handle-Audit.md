## Integration priorities and preserved evidence

1. Keep the current range ownership implementation: file-scope SlotRangeBindings has ComPtr arrays, invocation-local deferred results, safe kind QI, scoped indentation and exception handling. The upstream split is useful for readability but raw pointer ownership and operation->deferred mutation are not required for functional parity. No benchmark was run; no performance claim follows from splitting helpers.
2. Implement the explicit-bounds semantic migration before final examples/range CheckTO/dump tests. Preserve finite and integer range checks, nested expressions, inclusive physical element bounds, no mutation on invalid counts, CB bytes/constants conversion and slot API limits. Do not introduce the upstream function-local TargetInfo struct into new code; use file-scope existing types.
3. Treat cache_resource_data as one lifecycle change across load/reload, Map/Unmap, Update/Copy/Discard, custom snapshot propagation, HashRegion/SpatialHash and Store. In particular preserve ResourceHandleInfo::SetDataCacheRegion copy-on-write and CustomResource::SetHandleInfo null clearing, overflow checks and bounded view size. Preserve the new L3 mutex and in-frame invalidation; the upstream helper predates both fixes. No Resources-lock driver calls may return.
4. Store cache access must not bypass its existing physical bound/device/LOCKED checks or silently change failure-no-write to zeroing. A custom cache window has cached_data_offset, while Store remains absolute float-index into the backing buffer; translating between those coordinates needs a dedicated real buffer-window test.
5. Keep the CheckTO G lifetime guard around both matching and child execution when adding loops. A local element target prevents shared command mutation but does not make returned TextureOverride pointers safe after unlock.
6. Current local input-layout full-key cache/COM policy, generation identity, spatial 12/8/12 packing and FPS radius scaling, resource-properties views and structured Store safeguards are outside this batch and must not regress. None of the inspected commits requires a C++ standard increase, project-wide change, DX12 behavior change or upstream vcxproj adoption. Existing source files suffice; any chosen new helper source must be explicitly added to local CMake.

## Validation boundary

No new build, CTest, driver run, performance measurement or game session was started for this audit. After implementation use the repository DX11 build script, the real upstream regression executable through CTest with a 30-second timeout, and the compatible DX12 build when shared code changes. Actual swap-chain/shared-resource and target-game integration remain separate evidence. In particular documentation saying Store removes stalls is conditional on a valid fresh CPU cache and is not a measured end-to-end result.
