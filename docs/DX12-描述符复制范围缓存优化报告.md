## 本轮唯一生产改动

文件：`src/DirectX12/Tracking/DX12ResourceTrackerHooks.cpp`。

最终只为一次多范围 `CopyDescriptors` 调用维护一个**目标 heap 边界 memo**，源侧始终沿用原 resolver。原 resolver 的单个 sequential memo 被源/目标交替访问覆盖；重复 block 即使落在同一目标 heap，也会重新走 TLS 查找和刷新 sequential memo。

曾测试双 memo，但发现“每块来自不同源堆”的工作负载可能变慢，因此没有部署该方案。选择收益较保守、源侧完全不变的版本；8 个同目标堆的小块将完整 resolver 调用从 16 次降为 9 次，而不是省掉描述符处理。

新路径：

1. 对每个当前 handle 检查 memo 的 heap 起始地址、64 位范围、类型、increment 和当前 active 状态。
2. 每次重新计算 slot，不假定递增，不复用旧 slot。
3. 未命中调用原 `ResolveHeapSlotFast`，失败清除 memo；成功后保存当前目标堆的边界。源侧每次完整解析，不存在缓存旧源内容或旧源 slot 的路径。
4. 所有 descriptor 内容读取、valueId 比较、chunk/materialization 检查、锁回退、ledger 回退、槽发布和 heap commit 保持原路径。
5. memo 不跨 API 保存，不加入全局缓存或全局锁，不改变缓存容量，也不复用上次的 unchanged 结论。
6. Simple 和单范围调用走原 resolver，不为单个 block 填充 memo。使用调用栈上的 `std::optional` 懒初始化目标 memo，没有堆分配；Simple 不创建该存储，multi API 只有单范围时也不构造 memo。scope 不持有跨调用指针。

这不是“范围没变就不处理内容”。同一次 API 内即使源内容变化，后续 block 仍读取并复制新内容。

### 生命周期边界

正常 retire 保留 heap record/stateLocks，active 变为 false；同 CPU 地址的新 heap 是新 record，因此旧 memo 不能命中。边界缓存不会延长 COM 资源寿命。

`IsActive()` 不是 reader lifetime pin；retire 会清除存储和元数据，整体 cleanup 还会清空记录容器。本改动继承原同步 hook 的有效对象生命周期约束，不声称修复并发销毁或 cleanup 期间继续访问的问题，也没有以新增 generation 检查假装解决这些问题。

## 未改的路径

- UI 轮询约 0.36 ms/帧：改用消息队列键盘状态或降频不保持现有异步按键、组合键与 repeat 语义。
- SetPipelineState 约 1 ms/帧：包含原 API，已有同 PSO 快路与决策缓存；当前多数是真实 PSO 变化，不能把整段视为可消除成本。
- IA hash 约 1.2–1.4 ms/帧：已有 prefilter、slot 与 TLS 缓存，尚无证据支持进一步删除身份和失效校验。
- RootSignature 标量查询替代深拷贝有潜在小收益，但尚无独立耗时证据，本轮不扩范围。

## 回归与性能证据

`dev_tests/descriptor_copy_perf_test.ps1` 现在抽取真实 resolver（包含 global cache、TLS32、sequential predictor、RememberSequentialResolve、ordered map、deque 和 SRWLOCK），不再用 vector scan 来证明本次查找优化的收益。脚本保留当前源码/指定 Git baseline 的对比；所有实验源码替换与双 memo 开关已删除。

当前版和 `d0d15aa` 基线的 `/O2`、`/Od` 全部通过，随后 `/O2` 交替顺序各三轮全部通过。覆盖：

- 8 个不可合并 block 的 payload、identity、一次 heap commit，以及完整 resolve 从 16→9。
- 下一 API 的 memo 必须为空；Simple 和 multi 单范围都是 2 次原 resolve。
- 源/目标 heap 切换、随机/倒序/重复 handle、跨 4096-slot chunk。
- 边界、尾字节、零 handle、类型/wildcard、失败后再次解析。
- 串行 retire、清 metadata、同 CPU 地址注册新 heap。
- 同 scope 内修改源内容及 replacement generation、改变 materialization 后仍读取最新状态。
- 原有多种 payload、zero valueId、missing slot、ledger/hunt 回退分支、独立槽线程写入和 global cache 并发测试。

40-heap、每块来自不同源堆的诊断中，4000 次 API 的 destination L2 命中次数由 520 降为 80。计时区关闭 full-resolve 计数写入及 profiler 哈希计数，另设 diagnostic loop 验证调用数。
