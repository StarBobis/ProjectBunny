# DX11 final-feature audit

This is a read-only implementation-planning audit, not a migration or validation result. Order and full SHAs come from `docs/dx11-upstream-sync.json`: the 17 entries after `1d9403c0` through the observed `eae473b3` tip, plus `1d9403c0` as their SO prerequisite. Complete non-merge patches were read from the local upstream clone. Diff evidence is saved in `build/upstream/final-feature-audit/<short-sha>.diff.txt`; the three merge resolutions were separately inspected with `git show --remerge-diff` and saved as `.remerge.txt`.

Only this review document is changed by this audit. No build, tests, CMake, ledger, or production files were changed/run. Pending items below remain pending; suggested tests are not reported as passing.

## Concrete adaptation issues from the actual patches

### Texture state tracking

1. **Owned COM leak:** fdee `UpdateTextureGenerateMipsState` gets a resource reference from the SRV, then returns on `!info` inside the locked block before the trailing `resource->Release()`. Use ComPtr before any early return. Test an actual native/unregistered SRV and ref balance.
2. **Correct data lock:** new subresource vectors are documented under `mResourcesLock`, but 749 GetDhash uses `mCriticalSection`, then holds a raw ResourceHandleInfo after GetResourceHandleInfo's internal resources-lock scope. Snapshot fields under `mResourcesLock`; do not retain an unprotected handle across COM/GPU work. Local CriticalSectionGuard is a real named RAII macro, so it must be preserved; it is not a temporary-lock bug.
3. **Actual versus original descriptors:** fdee initializes mip/array counts from actual created desc but copy coverage checks use desc2D (retained original creation desc). Texture descriptor overrides can change width/height/mips. Store/query actual extents consistently for physical coverage while retaining original descriptors needed by hash matching.
4. **Deferred commands:** upstream advances global upload state while recording deferred commands, without a matching ExecuteCommandList publication mechanism. That can label not-yet-executed data uploaded and can invalidate/recompute against old GPU content. Decide and implement execution-aware publication or a conservative explicit unavailable state, preserving actual successful Execute semantics. Real deferred map/copy/execute tests are required; skipping a deferred compute call alone does not solve recording-time tracking.
5. **Coverage semantics:** null-box full updates initialize a subresource; partial updates preserve initialization only if already initialized; discard invalidates prior initialization. Empty boxes do nothing. Whole-copy source initialization is copied, not generation numbers. GenerateMips changes only selected slices/lower mips with initialized source. Test invalid indexes and zero-mip auto-generation descriptor expansion without allocating unbounded vectors. Generation zero is an unavailable sentinel; handle wrap without publishing an uploaded generation as zero.
6. **Map bookkeeping:** preserve buffer tracking and diverted-memory ownership when changing the map registry shape. Hoist initialized locals out of goto-crossed scopes for MSVC/C++17; new upstream Unmap declarations after early gotos cannot be copied mechanically. Failure/unmap/context destruction must not strand replacement allocations.

### dHash engine and cache

1. **False success:** 749 GetDhash sets out_hash=0 and unconditionally returns true at its end, including untracked resources or no eligible uploaded mip. Hamming/logging would therefore report a valid zero hash when no value was computed. Return explicit validity, preserving legitimate all-zero GPU output.
2. **One-call stale-cache glitch:** when a cached texture has changed and rehash is disabled, upstream only assigns dhash_generation=current generation, leaving out_hash zero and has_resource_dhash false. The next call returns the old cache. Return that old cached hash in the first call too, or apply a clearly equivalent retained-cache policy without a transient false value.
3. **Publication race:** mip/generation selection happens before compute, but publishing records whatever resource_generation exists afterwards. If an upload occurs during compute, old GPU results can be marked current. Capture generation/mip and validate them again before publish; failure/retry must not mark stale data fresh. This needs an actual controllable publication test or concurrency protocol test, not only two sequential calls.
4. **Cache identity:** source view sampling format (linear versus sRGB, typeless view interpretation) can change dHash without changing resource generation. Resource-generation-only cache keys can return a prior format's result. Define identity including sampling format and selected-mip policy, and test distinct views of one physical resource. Rehash false is intentionally retained-content behavior; do not accidentally change that policy while fixing key correctness.
5. **View type:** cb2 passes generic ID3D11View from frame analysis, while 749 casts it directly to ID3D11ShaderResourceView before GetDesc. Use QI or the existing safe GetViewInfo mechanism; RTV/UAV/DSV are not SRVs. Never interpret an incompatible view union.
6. **GPU state / hazards:** engine saves CS shader/class instances, SRV0, sampler0, UAV0, but binding an input texture already used as an output can force null input/other binding changes. Test CS UAV1 and OM RTV/UAV aliases as well as the ordinary CS0 state. Restore every state changed by the chosen strategy, or reject/avoid conflicting input before dispatch. Use the real pass-through context to avoid recursive hook/profiling/tracking calls. Internal compute must not contaminate application shader tracking.
7. **Unsupported format:** CheckFormatSupport lacking SHADER_SAMPLE currently logs but continues. Reject unsupported sampling instead of returning an apparent computed zero. Test integer/typeless-with-valid-view, sRGB, unsupported formats, array/MSAA/mip errors and device mismatch. Deferred contexts must fail without dispatch or readback.
8. **Staging descriptor:** a217 copies the structured UAV buffer descriptor to staging and clears BindFlags but retains BUFFER_STRUCTURED/stride alongside CPU_ACCESS_READ. Validate CreateBuffer on real WARP; use the established plain readback descriptor if the misc/CPU-access combination is rejected. This is an unexecuted descriptor concern, not a measured failure here.
9. **Lock-free GPU work:** cb2 invokes GetDhash while FrameAnalysisLogResourceHashInline still holds both G and resource locks. Snapshot logging metadata, release locks, then compute and append. Optional G->mResourceInfo.at(orig_hash) can throw before reaching the dHash call; absence of contamination metadata must not suppress an otherwise valid dHash.
10. **Reference semantics:** original_format/original_dhash must initialize for every constructor, template, lazy object and reset path; configure/copy_desc through CopyMetadataFrom; propagate through all actual copy/reference paths, including range fast paths fixed in the preceding batch. The reference hash is metadata, not the resource's pixel content; absence versus legitimate zero needs an explicit documented contract.

## Suggested validation and integration sequence

1. Complete SO offset/append/reference helpers and docs first. Compile a real stream-output GS with two output buffers. Issue draws, replace one target at a nonzero Region offset, draw again and read back both buffers. Check untouched target append, all four dynamic slots, null replacement, failed Region bounds, repeated self-reference, GS lifetime and deliberate lack of hunting/declaration registration. The earlier dynamic SO identity regression cannot establish output offsets or append behavior.
2. Add shader declaration summaries to the existing safe parser and snapshot interface, then PS-only dump filtering. Reflect compiled sparse typed/raw/structured shaders as oracle; verify actual file count/contents and fetched-view lifetimes in a build directory.
3. Add Resource metadata defaults/INI/copy/template paths independently of dHash, preserving enum bits and current format override rules.
4. Land texture-generation state and all actual wrapper hooks with real WARP uploads, simultaneous subresource map records, copies, GenerateMips, Resolve, deferred execution, release/reload and invalidation tests. Keep full/partial initialization semantics explicit.
5. Add DHash64Gpu to **DX11 only** CMake and inherited production regression sources. Existing target already links d3dcompiler.lib; the HLSL is embedded, so there is no external shader copy/deployment requirement. Verify compile failure/retry, COM destruction and immediate-context lifecycle. A CPU reference sampler on controlled textures should match the actual 9x8 linear-sampled comparisons, channel averaging and zero-gradient RGBA thermometer fallback (not a generic grayscale-only dHash).
6. Add orchestrator and frame-analysis integration after engine correctness. Exercise valid zero, unavailable, hit/miss, no-rehash first call after upload, allow-rehash selected latest mip, format-sensitive cache entries, generation races, failure retry and lock boundaries.
7. Add Hash/Resource member arguments and HammingDistance, preserving parse rollback and immutable per-run target ownership. Real INI loading must prove original_dhash/original_format and Rendering options feed the getter. Test two resources with known GPU hashes, exact 64-bit reference values, zero special cases and all error sentinels.
8. Run actual full C++17 DX11 DLL plus regression build and CTest, then document target-game checks separately. If shared utilities are changed, run the established DX12 compatibility build too. This audit itself ran none of those commands and does not mark any commit validated.
