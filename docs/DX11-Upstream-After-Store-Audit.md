## Shader-resource context, state and lifecycle

The local source inspected here uses ShaderResourceBindBatch::run -> operation->RunWithBinding(state, local_sink) and fetch -> operation->RunWithSource(...). Both entry methods are currently nonvirtual, and eligibility deliberately checks exact ResourceCopyOperation typeid. A direct copy of the upstream virtual run override would therefore never select the conditional branch on the bind path. Adapt those local entry points deliberately and whitelist the new folded type without making arbitrary derived operations batchable. Keep invocation-local deferred output; do not restore shared branch->op->deferred pointers, which race across contexts and can remain set after exceptions.

Batch grouping and runtime indexing must use the same actual branch target. Test a run whose lowest slot is nonzero to detect the initial default-slot-zero bug. Preserve original operation order across duplicate slots and aliases. A condition that reads ps-t0 or metadata after a preceding bind must see the preceding binding, so that chain remains a batch barrier. Dynamic pool index expressions remain barriers for the same reason. Static probes must not consume random values; count-based random observation is already available locally. Conditions are evaluated at execution, with original short-circuit branch ordering.

The existing local lazy flush seeds only actual untouched slots, including gaps, missing else and unless_null. Keep this behavior when introducing upstream may-keep metadata, and retain no Set when all operations skipped. Retain RAII views, valid slot/count checks, partial-prefix publication on exception, and flags/resource-pool lifetime. Source_if owns the original If expression objects; replacing or clearing batches must not leave branch condition pointers dangling. Pre/post phase selection must prevent all-pre assignments from running a second time in post.

No measured speed or API reduction is implied by this audit. Meaningful evidence combines actual WARP bound views/data/side effects with existing production Get/Set call instrumentation. The target-game concurrency/driver behavior is separate evidence; these tests would not establish all legacy globals or pool caches thread-safe.

## Stream Output validation required

Use a real WARP shader compiled with a stream-output declaration, bind the target through the production resource command, issue a draw and read the resulting buffer. SOGetTargets returns resources, not offsets, so a pointer/descriptor assertion cannot prove offset handling. Verify an explicit Region writes the emitted value at the selected byte offset while prefix bytes remain unchanged; a small Region size must not be misrepresented as a native SO size limit, because only offset is consumed. Unmentioned slots retain upstream offset zero, not append -1. Test ordinary and explicit Region sources as offset zero reads.

Test reference ownership with an independently held caller resource, replacing a previously bound target, null unbinding, repeated same-resource binds and a second unrelated slot. Returned SOGetTargets references must be balanced, while the replacement callers reference must survive. Include actual destruction/COM-reference evidence where available, not just matching pointers. Test deferred and immediate contexts separately if claiming both. Native API alignment/slot/resource validation should leave existing bindings intact on rejected inputs; retain local source/Region validation and avoid adding a guessed offset-tracking cache to approximate state the native API cannot report.

## Existing local equivalence and safety constraints

- TryGetSpatialHash is already safer than 57a1b6: each byte offset is bounded by subtraction, final valid float is accepted, reads use memcpy, nonfinite values and invalid cell sizes are rejected, and zero hash is a valid result. Existing tests in tests/upstream_regression.cpp cover distinct Y/Z and boundary/overflow. No rewrite to upstream index*4/max math is needed.
- Explicit Region already has local physical copy bounds and legal CB reference-window distinction. Tests/resource_region_regression.cpp contains actual selected-byte readback for (256,512), (20,32), (3,16), CB windows and invalid/no-change cases. These are evidence of existing intended behavior, not proof that every new non-CB/conversion path is equivalent. SpecialCopyBufferRegion still needs safe arithmetic review.
- Preserve C++17, shared expression ownership, file-scope helper types, native view kind checks, structured Store alignment, current input-layout cache/COM policy, cache_resource_data lifecycle, L3 independent mutex/in-frame invalidation, 12/8/12 spatial layout/FPS radius, and CheckTO match+consume G-lock scopes. None of these commits requires DX12 changes or an upstream project-file transplant. New helper files, if chosen, need explicit local CMake registration.
