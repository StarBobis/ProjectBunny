# 代码规范
- 修改代码前，必须去查询DX12官方文档以佐证自己的思路。
- 如果你要靠猜才能验证的话，不妨看看Github上关于RenderDoc、ReShade、RenoDX等常见DX12项目是如何处理类似情况的，也可以自行上网搜索相关文档。
- 允许失败，因为失败了会积累经验，也就是说如果你觉得做不到，就要告诉我做不到。
- 我喜欢逻辑推理得到的结果，而不是靠猜。
- 当我让你和某某项目代码对齐颗粒度时，不要"补一颗螺丝测一次"，而是成体系的颗粒度对齐！ 大幅度更改，别老每次改一点点浪费我测试时间 ！
- 尽可能使用面向对象编程而不是函数式编程，否则代码难以维护。
- 工具类尽可能声明在.hpp中，不要将函数代码散落在.cpp中，且命名应该严格以Utils结尾
- 所有编写的class，不得有任何private属性和方法，所有属性和函数都必须是public的，这样就不用写额外的getter/setter函数了。
- 代码尽量放在某种class或者某种Utils.class中，除非架构设计需要，否则不允许独立散落函数导致难以维护。
- 绝对禁止使用auto，所有类型必须显式声明！
