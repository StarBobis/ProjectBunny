# 2026-07-01 Hunt双状态模型清理经验

## 背景

这次继续排查“仅代码问题导致 CPU 额外无效操作”时，确认了目前最重的一类结构性错误：

- `DX12CommandListRuntime` 已经维护了一份 command list 的 PSO / IA 运行时状态
- `DX12ShaderHunt` 又额外维护了一份 `gCommandListPso` / `gCommandListIa`
- draw / dispatch / execute-indirect / skip 判定 各自围绕这两套状态来回转

这不是普通的重复代码，而是典型的双状态模型错误：

- 同一个事实有两份真相源
- 两份真相的更新时机不完全一致
- 一处修改后，另一处很容易继续沿旧架构补壳

## 这次确认下来的结论

### 1. Hunt 不应该拥有 command list 状态，只应该消费 command list 状态

Hunt 模块真正的职责是：

- 记录 visit
- 维护 selection
- 决定 skip
- 刷新 overlay

它不应该再承担：

- 记住当前 PSO
- 记住当前 IA buffers
- 在 reset / clear / IA 设置时复制一遍 command list 状态

换句话说：

- `DX12CommandListRuntime` 是状态源
- `DX12ShaderHunt` 是状态消费者

而不是两个模块都持有状态。

### 2. 删除双状态模型时，必须先补齐单一状态源在所有模式下的更新

这次如果只删 `gCommandListPso/gCommandListIa`，但不补齐 runtime state 在 hunt-only 快路径下的 IA/PSO 更新，就会出现：

- 架构上看似只剩一份状态
- 实际上那份状态在 hunting 场景里不完整

因此正确顺序是：

1. 先让 hunt-only 路径也写 `DX12CommandListRuntime`
2. 再让 Hunt 改成只读 `DX12CommandListRuntimeState`
3. 最后删掉 `gCommandListPso/gCommandListIa`

### 3. `Reset` 语义必须对齐到真正的状态源

原来 `DX12HuntResetCommandList()` 会清掉 Hunt 自己那套 IA/PSO 副本。
当 Hunt 不再持有副本后，真正需要 reset 的就变成：

- runtime PSO
- runtime IA
- hunt visit 统计

所以 `Reset` 的关键不再是“清掉 Hunt map”，而是“保证单一状态源被重置”。

## 这次踩到的坑

### 1. hunt-only 快路径以前只更新 Hunt 自己，不更新 runtime

比如 skipBindings 的 IA 快路径里，旧架构会直接：

- `DX12HuntSetIndexBuffer`
- `DX12HuntSetVertexBuffers`

而不更新 `DX12CommandListRuntime`

这说明旧设计默认 Hunt 有自己的一套状态仓库。删除双状态模型时，必须整条链替换，不是只删 `.cpp` 里的 map。

### 2. “Hunt 只需要 skip 判定”并不意味着它不依赖 IA 状态

如果简单认为 Hunt 只是看 shader hash，就会漏掉：

- IB hash
- VB hash
- draw 参数和 IA view 组合后的 region hash

所以重构时不能只把 PSO 改成 runtime 来源，还必须把 IA 也改成 runtime 来源。

## 后续继续排查时的纪律

- 只要同一个概念已经有 runtime state 模块，就优先怀疑别的模块里那份 map/cache 是副本而不是真 seam
- 遇到 `SetXxx / ResetXxx / ShouldSkipXxx` 同时分布在两个模块里维护同一事实，优先怀疑双状态模型
- 清理双状态模型时，先补齐唯一状态源的更新，再删消费者副本
- 删除时按整条调用链处理：状态写入、状态读取、reset、toggle 清理逻辑都要同步改

## 这次修改的直接收益

- `DX12ShaderHunt` 不再维护 `gCommandListPso/gCommandListIa`，命令列表状态真相源减少到 1 份
- Hunt 路径里围绕 PSO / IA 的重复 map 写入和读取减少 100%
- `Draw / Dispatch / ExecuteIndirect / skip` 对 command list 状态的理解收敛到 `DX12CommandListRuntimeState`
- 在不改变 dump 完整性和 mod 生效语义的前提下，预计整体 CPU 开销再下降 0.3% 到 1.0%；在 Hunting 场景里，预计可提升 1% 到 3%，同时后续围绕 Hunt 的维护误判风险预计下降 70% 以上
