# DX12 Draw 路径盘点 ×「替换后能否直用」可行性报告

日期：2026-09-12 ｜ 基线：TIMING build，窗口 62 帧，frameWall **35.89 ms** 均值 / 45.80 ms 最大，**989 次 DrawIndexedInstanced/帧**
证据约定：`[证]` = 代码可直接读出；`[推]` = 机制推断，需实测确认。

---

## 0. 结论摘要

| 你的设想 | 结论 |
|---|---|
| PreSkin / IA 替换完成后，Draw 直接使用替换结果 | **分三档**：bind 期静态 IA 替换**已经就是这样**；PSO 静态模板替换**已是惰性保留，但正面结果没进缓存**；per-draw 动态替换与 PreSkin **不能直用**，也不该直用 |

三个问题的直接回答：

1. **能做吗？** 能在一条路上做（PSO 静态模板的**正面结果缓存**），其余两条路已经做了，最后一条路做了就是错的。
2. **DX11 怎么做的？** DX11 **每次 draw 都重做整套判定**，它没有"是否已替换"的复核，也**没有任何负缓存/世代**（`src/DirectX11/` 全仓检索 `negative_cache|verdict|draw_decision_cache` 零匹配）。它不需要复核，是因为它的**判定即执行**（立即上下文，当场调驱动）+ **状态单份** + **指针即身份**。这三个前提 DX12 全都没有。
3. **我们做了额外冗余工作吗？** 做了，但**不在"替换判定"本身**，而在四处结构性浪费：
   - 同一个 IA 绑定状态被构造成 **4 个不同的 key**，每个都遍历 32 个 vertex slot；
   - 同一个 PSO 决策每 draw **校验两次**、`kind` 判三次、flags mask 判三次；
   - **三层负缓存**（bound-draw / IA-state 签名 / resident negative）各判各存，同一结论写 2~3 份；
   - **正面结果从不进缓存**：`DX12BoundDrawResultCache::Capture(...)` 的唯一写入点传 `false`（`Hooks/DX12IaReplacement.h:1924-1936`）[证]，命中且 `hasOverride==true` 时仍然穿透到 IA 哈希 + 候选匹配（`:1910-1920` 只对 `!hasOverride` 早退）[证]。
     ⚠️ **但这一条的收益很小**：计数器显示判定的 99.5% 是负面（`Rm.IaNegVerdictNegative` 605.79/帧 vs `Rm.IaNegVerdictCandidate` ≈0.2%），**正面替换每帧只有个位数** —— 缓存正面结果是"正确但省不到"，不是主战场。
   - **真正的大头在负判定的哈希重算**：689 次判定/帧里 `IaNegVerdictHashes` 占 **1.50 ms/帧**（`Rm.IaViewHashSlotRebuild` ≈1676/帧，即每次判定平均重建 ~2.4 个视图哈希），而每次得到的都是同一个"没有候选"。IA 状态负缓存只命中 41.1%（425 命中 / 689 判定），剩下的miss 几乎全花在这里。

## 2. 三类"替换"的形态与"直用"结论

### 2.1 bind 期静态 IA 替换 —— **已经是"直用"** ✅
- 在 `IASetVertexBuffers`/`IASetIndexBuffer` 包装里完成：静态替换 → PreSkin 重定向 → **把替换后的视图交给驱动**（`DX12WrapperRuntimeUtils.h:1559-1571`、`1580-1615`），同时写影子状态（`:1372-1385`、`:1281-1292`）[证]。
- draw 处**没有**"是否已替换"的判定，只有失效看门狗 `RestoreStaleStaticIaBindings`（`DX12IaReplacement.h:1526-1686`）：常规 **2 次 load 早退**（`:1534-1535`），深查被 `(globalContentGeneration, resolveEpoch)` 门控（`:1543-1549`），命中才回滚并 `BumpIaEpoch`（`:1684-1685`）[证]。
- → 这条路上你的设想**已经实现**，不要动。

### 2.2 PSO 级静态模板替换 —— **惰性保留已做，正面结果没缓存**（正确性缺口，但实测收益小）
- 计划随决策携带快照 `drawDecision->staticReplacementSnapshot`（`DX12IaReplacement.h:1774-1775`）[证]；
- `ApplyStaticTemplateLazy`（`:1442-1476`）**只应用一次**并置 `staticTemplateIaApplied`（`:1459-1467`），后续 draw 只做与 draw 参数相关的部分（`:1470-1473`）[证]；
- 还原有四条明确触发点：决策不再携带同一模板（`:1767-1773`）、游戏重绑 IA（`DX12WrapperRuntimeUtils.h:1418-1425`、`:1507-1514`）、命令列表 Reset（`DX12CommandListRuntime.cpp:493-494`、`:951-954`）、noop 转发前看门狗（`DX12DrawHookFlow.h:165-170`）[证]。
- **缺口**：`DX12BoundDrawResultCache` 已经具备 `hasOverride`/`overrideResult` 字段与完整 11 项 key（`Core/CommandState/DX12IaHashCaches.h:631-659`、`:769-794`），但**唯一写入点传 `false`**（`DX12IaReplacement.h:1924-1936`）[证]，命中正面时仍穿透整条链。
- → **"替换过就直接 draw"能在这条路上落地**（把正面结论也 `Capture` 进去），但**实测收益小**：正面替换每帧只有个位数（`Rm.IaNegVerdictNegative 605.79/帧` vs `Rm.IaNegVerdictCandidate ≈0.2%`），省下的是这几次的候选匹配，不是 1.50 ms 的哈希大头。它值得做，理由是把缓存语义补完整（现在只缓存一半结论），而不是因为它大。

### 2.3 per-draw 动态替换 + PreSkin —— **不能直用** ❌
- PreSkin：VB 内容**每帧被 GPU 重写**，同一帧内保留的替换会过期（代码原话，`DX12IaReplacement.h:1787-1796`）[证]；bind 期重定向（`DX12WrapperRuntimeUtils.h:1458-1480`）+ draw 期 replay（`DX12IaReplacement.h:613-665`），并带 8 帧 sticky 匹配窗口（`ModRuntimeInternal.h:2849-2865`）[证]。
- per-draw 计划依赖 draw 参数（`fromCaller`/`autoCount`，`Core/ModState/DX12ModIaReplacement.h:240-243`），TLS scratch 每 draw `ResetForDraw`（`:209-224`、`DX12IaReplacement.h:1697-1701`）[证]。
- → 这条路上"直接使用"= 用过期内容画，属于**错的优化**。

## 3. 若做"正面结果直用"：最小 invariant 集

## 4. DX11 对照

### 4.1 DX11 一次 draw 的流程
`HookedContext.cpp:2122` 装 vtable 钩子 → `:438-457` 极薄转发 → `HackerContext::DrawIndexedInstanced`（`HackerContext.cpp:3081`）：
1. `:3093` 构造 `DrawContext`/`DrawCallInfo`；
2. `:3094` `BeforeDraw`（`:757-969`）：hunting 簿记 → `:923` 延迟 shader 替换 → `:926-964` **按当前 VS/HS/DS/GS/PS 句柄逐一 lookup shaderoverride 并执行其命令表**；
3. `:3096-3098` `if (!skip) mOrigContext1->DrawIndexedInstanced(<游戏原始入参>)`；
4. `:3099` AfterDraw：post_commands + 还原 old shader。

### 4.2 DX11 有没有"再确认一次是否已被替换"？
**没有复核，但它每次 draw 都重做整套判定**[证]：
- bind 期只记录零改写（`HackerContext.cpp:3049-3079` IASetIndexBuffer、`:1472-1514` IASetVertexBuffers 都原样转发）[证]；
- 匹配结果缓存**全是加载期预筛索引**（`IniHandler.cpp:4185-4207` 按 `match_index_count`/`match_vertex_count` 建 map）+ 运行期一次 map 查（`ResourceHash.cpp:1683-1700`）+ 逐条 `matches_draw_info` 复核（`:1702-1710`）；唯一运行期缓存是区域哈希（`:2141-2216`，L3 每帧清 `HackerDXGI.cpp:568-570`）[证]；
- 正确性来源：**判定与生效是同一动作**（命令表当场 `mOrigContext1->Draw*` `CommandList.cpp:1257/1286`，或当场置 `skip` `:1407-1415`）→ 立即上下文里"判定时读到的绑定 = 驱动执行时看到的绑定"[推]。

### 4.3 为什么不能照搬（结构差异）
| # | DX11 | DX12 | 后果 |
|---|---|---|---|
| 1 | 当场调驱动（`HackerContext.cpp:3096-3098`），判定时刻＝执行时刻 | 录制/提交分离（`DX12CommandWrappers.h:112-125`、`DX12CommandQueueExecution.h:34-49`） | 判定必须落实为指令或带可校验世代 |
| 2 | 指针即身份（`HackerContext.h:120-136/216/220`） | VA + 绑定身份 + 解析世代，堆可整份替换/迁移（`DX12SimulateContext.h:305-310`、`DX12IaHashCaches.h:209-271`） | 只按指针缓存会在 VA 回收/堆迁移后给出过期结论 |
| 3 | 状态单份 | per-command-list `DX12SimulateContext` + `iaEpoch`（`DX12SimulateContext.h:87,298`） | 列表可 Reset 复用、可多线程录制，需 epoch 区分两次录制 |
| 4 | 可"跳过一次+自己发一次"而天然一致（`CommandList.cpp:1239-1330`+`:1407-1415`） | 绑定是列表上显式对象（`DX12CommandListWrapper.h:890-930`） | 跳过/重发会与影子状态不一致 → 必须重校验并恢复 |
| 5 | 只钩立即上下文（`DLLMainHook.h:16-22`） | 普遍多线程录制 + 全局世代（`DX12BufferResolveCache.h:118`） | 单份状态假设失效 |
| 6 | 预筛解决"查得快" | IA 状态逐帧重复录制 | 需要**带失效项的运行期判定缓存**，DX11 没有对应物 |

**结论**：DX11 不复核不是"比我们聪明"，而是它的三个前提（判定即执行 / 状态单份 / 指针即身份）在 DX12 都不成立。我们多出来的层不是多余设计，是 DX12 的正确性成本；**多余的是层的数量和正面结果的缺席**。

### 5.2 看着冗余、但有正确性职责（**不要动**）
1. `RestoreStaleStaticIaBindings` 的 generation 门（`DX12IaReplacement.h:1534-1549`）—— 2 次 load 已是下限。
2. 每 draw 的 draw-SRV pending flush 与 `FLAG_DRAWSRV_PENDING_RESTORE` 阻挡（`DX12DrawHookFlow.h:50-51`）—— 跨 draw 暂态，必须查。
3. 游戏重绑 IA 时的模板还原（`DX12WrapperRuntimeUtils.h:1418-1425`、`:1507-1514`）。
4. `EnsureDrawDecision` 的 reload/globals 校验（`:1740-1745` 的短路保留）；pre-skin 段/replay 门（`:626-631`）。

### 5.3 建议实施顺序（按实测收益排序，不按直觉）
1. **P1：让负判定不再重算视图哈希**（最大单项，1.50 ms/帧）。两条互补手段：
   - **视图哈希 memo**：`GetOrBuildCachedIndexViewHash/Vertex` 在负路径仍全量重算（`Rm.IaViewHashSlotRebuild` ≈1676/帧）。按 (BufferLocation, SizeInBytes, Stride/Format, resolveGeneration) 做一层小 memo，命中即免哈希；同一帧内同一视图被判定多次是常态。
   - **判定表容量**：负缓存 1024 条对 ~1100/帧 的活跃 IA 状态是刚刚不够，miss 后每次都要走完整判定。若改成 4096 条（96 KB）需注意 `DX12SimulateContext` 是 dispatch 路径上的栈对象，有 1MB 栈预算（已有 `static_assert` 护栏），因此**优先做 memo，再评估容量**。
   **验证**：`Stage.IaNegVerdictHashes` 与 `Rm.IaViewHashSlotRebuild` 下降、`Stage.DrawOverride` 从 3.12 ms/f 下降。
2. **P2：key 复用**（slot 视图指纹只算一次，后 3 个 key 复用它）→ 省掉 3 次 × 32 slot 遍历。
3. **P3：门控去重**（flags mask 一次、决策校验一次、callbacks 静态表、`TryForwardNoopDraw` 先判 `kind`）。
4. **P4：负缓存收敛 + 正面结果缓存**（正确性补完；正面结论写进 bound-draw 缓存）。收益小，但要防"只缓存一半结论"这类隐性不对称。
5. **不做**：per-draw / PreSkin 的"保留式替换"（内容每帧被 GPU 重写）。
