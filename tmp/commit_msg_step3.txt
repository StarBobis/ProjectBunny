ModRuntime IB 匹配键流切换为内容哈希·第3步

- GetOrBuildCachedIndexViewHash（DX12CommandListRuntime.cpp）：IB 身份改为
  DX12HashIaBufferContent（'DXIC' 内容哈希，与 hunting 绿字同值，stride=0/format=索引格式/slot=0）。
  删除按 resolve 代际校验的 slot 级缓存：它对内容哈希会在 CPU 改写后无限期供出陈旧值；
  缓存交由 D4 memo（按每资源内容代际逐命中校验）。ia->indexBufferHash* 字段保持 invalid，
  负缓存快照（DX12ModBuildIaStateNegativeHashSnapshot）随之始终委托该函数。
  miss=0 时匹配点 fail-open（0 本来就是 wildcard 查询键语义），异步读回晚一帧生效
- ApplyIaStateResourceOverrides（DX12CommandListExecutor.h）：IB 回填改用
  DX12HashIaBufferContent（替换后 view 同参数约定），同源身份注释同步为内容哈希
- TryRedirectStaticIaIndexBuffer（DX12WrapperRuntimeUtils.h）：view 级与整资源兜底两级
  查询键都改 DX12HashIaBufferContent，保留两级查表结构；现有 if (hash && device) 与
  DX12ResolveStaticIaReplacement 的 !contentHash early-out 已保证 0 fail-open，不加新特判
- DX12LoadedResources.cpp：新增文件级 PublishLoadedBufferContent，两个 mod buffer 创建点
  （BuildLoadedBufferResource / EnsureLoadedResourceForPreSkin）在 Unmap 后把完整 byteWidth
  （含零填充尾——页缓存按整页校验，只发 bytes.size() 会在 byteWidth>bytes.size() 时永远 miss）
  发布进页缓存；发布键为 DX12WrapperRuntimeUtils::UnwrapResource 后的原生指针
  （VA 解析索引记录的是包装前指针）；Unmap 钩子对本 DLL 调用方会 invalidate 内容项，
  故发布必须在 Unmap 之后。发布后即以该 view 参数自检查 DX12HashIaBufferContent，
  返回 0 打 DX12_LOG 告警（content_hash_unready，开发期验证，不断言、不影响流程）
- 注释同步：DX12IaHashCaches.h 负缓存签名（内容哈希由上游 memo 按内容代际校验，
  hash 值本身在签名内）；DX12ModState.h / DX12ResourceContentHashing.cpp 的
  "no consumers yet" 注记更新为消费者清单（Hunting 第2步已切 + 本步 Mod Runtime IB 键流）
- VB 一律不动：GetOrBuildCachedVertexViewHash、Executor VB 回填、静态替换 VB 两级、
  dump VB 继续用 DX12HashIaBufferContentView；draw-region 兜底（DX12IaRegion::Hash* /
  DX12TextureOverrideMatching.cpp:1399）、INI 解析、BuildDx12IaTextureOverrideIndex /
  BuildDx12StaticIaReplacementTable、匹配/过滤/负缓存逻辑零改动
- 已知缺口：dump 侧（DX12BindingExport 等）仍是元数据哈希，第 4 步补齐；
  过渡期内 mod 作者以 hunting 绿字哈希为准
